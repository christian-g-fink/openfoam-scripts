In this project, I want to replicate the functionality of the script /home/tcgfink/Documents/research/sleep_apnea/upper-airway-segmentation/pyfluent_script/run_cfd_simulation.py, but in OpenFOAM rather than in ANSYS Fluent. This is intended to eventually serve as the foundation of commercial software for ENTs, oral surgeons, and orthodontists to use to guide surgery for nasal congestion.

The file ../pyfluent_script/fink_06_05_2024_fluent.cas.h5 contains the meshed model to run the CFD simulation on. I want to test the OpenFOAM simulation on the exact same mesh (generated by ANSYS) and then compare the results to those generated by Fluent (../pyfluent_script/fink_06_05_2024_fluent_solved_flow.csv, produced by ../pyfluent_script/analyze_flow.py).

## Commercial and regulatory constraints

- Use ESI OpenFOAM (openfoam.com): stable API and paid support available. OpenFOAM is GPLv3; call its stock executables as separate processes and drive everything through case dictionaries (no custom solvers linked against OpenFOAM libraries), so proprietary code stays separate. "OpenFOAM" is a trademark of OpenCFD/ESI; don't use it in product names.
- Likely FDA software as a medical device (SaMD), probably Class II. Keep in mind IEC 62304 (OpenFOAM is SOUP: pin versions), FDA's 2023 computational modeling credibility guidance, and ASME V&V 40. Keep the pipeline scripted and reproducible; the Fluent comparison is verification evidence.

## Pipeline

1. `export_fluent_mesh.py` (done; needs VPN): Fluent's solver can't write a bare .msh, so this reads the .cas.h5, disables CFF and binary output, and writes a text legacy case as `<stem>.msh` (105 MB), plus `<stem>_materials.json` with the fluid properties. This is the only step that needs an ANSYS license.
2. `fluent3DMeshToFoam <stem>.msh` (done; takes about 2 s) converts the mesh into OpenFOAM's format. Use it rather than `fluentMeshToFoam`: the mesh is polyhedral. Coordinates are already in metres (no `-scale`). Its log says it writes to `constant/region0`, but the files land in `constant/polyMesh` as usual. Result: 272,367 cells (85% polyhedra), 710,562 points, volume 47.74 cm³, one connected region. Six patches, all type `patch`, so boundary conditions are set in the 0/ files: nasopharynx, rightnasalcavity, leftnasalcavity, leftinlet, rightinlet, outlet.
   - `checkMesh` mesh quality: max non-orthogonality 79.9° (1,948 faces above 70°), max skewness 7.8, and about 8.7k faces where OpenFOAM's tet-decomposition check fails. These are typical for Fluent polyhedral meshes and Fluent tolerates them; in OpenFOAM, use non-orthogonal correctors and limited gradient/laplacian schemes.
3. `run_cfd_simulation.py <stem>.msh` (written; first full run in progress): builds the case `<stem>_solved_flow/` with foamlib, converts the mesh, runs checkMesh, decomposePar, `mpiexec simpleFoam -parallel` and reconstructPar, then prints the flow rates and outlet pressure and writes `run_info.json` (OpenFOAM version, mesh SHA-256, settings, convergence). Options: `--processors` (default 6), `--iterations` (maximum, default 2000), `--mass-flow-rate`, `--convergence`, `--materials`, `--case-dir`, `--overwrite`. Function objects log per-iteration flow rates (sum of phi) and area-average p at the inlets and outlet to `postProcessing/`. OpenFOAM's flow-rate sign convention is the opposite of Fluent's (outflow is positive).
   - foamlib quirks: multi-word dictionary values must be tuples of words; field entries other than `value` need an explicit `("uniform", x)`.
   - First full run (2026-10-31, in `fink_06_05_2024_fluent_solved_flow/`): converged to 1e-4 in 337 iterations (155 s on 6 processes). A rerun to 1e-6 converged at iteration 501, and its values moved less than 0.02% from those at iteration 337, so 1e-4 is tight enough.
   - Remaining differences from Fluent are therefore not convergence but differences between the solvers (discretization, gradient limiting, boundary treatment): outlet p −4.861 vs −4.702 Pa (3.4%), left/right inlet flow 145.0/105.0 vs 143.7/106.3 cm³/s (+0.9%/−1.2%), left/right inlet p −0.855/−0.480 vs −0.844/−0.498 Pa (1.2%/3.7%). Not yet checked: whether Fluent's fixed 200 iterations were fully converged, and scheme sensitivity (e.g. removing cellLimited on grad(U)).
4. `analyze_flow.py <case_dir> --choana-z 0.083 [--compare <fluent.csv>]` (done): OpenFOAM equivalent of ../pyfluent_script/analyze_flow.py. Same interface (exactly one of `--choana-x/y/z` makes a YZ/XZ/XY plane), same CSV metric names and order, same sign convention (positive = entering the domain), same resistance formulas (|p_choana| / Q). Writes `<case_dir>.csv` next to the case, `<case_dir>/analyze_flow_info.json` (choana area and flow-through diagnostics), and with `--compare` a `<case_dir>_vs_fluent.csv` with percent differences. Uses `postProcess -dict system/analyzeFlowDict -time <latest> -fields '(p U phi)'` with surfaceFieldValue function objects; the choana is a cuttingPlane sampled surface.
   - postProcess quirks: it doesn't load fields unless they are passed with `-fields` (without that it warns "Requested field ... not found"; a first pass printing those warnings is normal). Output goes to `postProcessing/<name>/<first time processed>/`, not necessarily the solution time. surfaceFieldValue on a sampled surface always uses cell values (`interpolationCell`); a sampledSurfaceDict `interpolate` setting has no effect.
   - Results for fink_06_05_2024 (z = 0.083): choana p −4.517 vs Fluent −4.392 Pa (2.9%); resistances total/left/right 0.01807/0.03115/0.04303 vs 0.01757/0.03056/0.04131 Pa·s/cm³ (+2.9%/+1.9%/+4.2%). Choana plane area 3.794 cm². The flow through the plane is 252.8 cm³/s (1.1% high, because integrating cell-centre velocities is not conservative). The choana pressure is insensitive to plane position: −4.5166 to −4.5174 Pa for z = 0.0829 to 0.0831, even though the wall patches split exactly at z = 0.083.
5. Later: energy transport and heat flux analysis (the equivalent of analyze_energy_transport.py).

## Simulation setup (Fluent equivalents)

- Steady, laminar, incompressible: `simpleFoam` with `simulationType laminar`. (Fluent: coupled pressure-velocity solver, second-order schemes.)
- Air properties come from the Fluent case (not Fluent's defaults of 1.225 / 1.7894e-5): ρ = 1.2 kg/m³, μ = 1.8e-5 Pa·s, so ν = 1.5e-5 m²/s and 0.0003 kg/s = 250 cm³/s. Read them from `<stem>_materials.json`. OpenFOAM's incompressible pressure is p/ρ; multiply by ρ to get Pa.
- Inlets (leftinlet, rightinlet): Fluent pressure inlets at 0 Pa gauge → `totalPressure` with p0 = 0.
- Outlet: Fluent mass-flow outlet → `flowRateOutletVelocity` with volumetricFlowRate = mass flow / ρ.
- Walls (nasopharynx, leftnasalcavity, rightnasalcavity): no-slip.
- Stop when residuals reach 1e-4 (residualControl), with a maximum iteration count, since SIMPLE needs more iterations than Fluent's coupled solver (200).
- Second-order schemes (linearUpwind for velocity).
